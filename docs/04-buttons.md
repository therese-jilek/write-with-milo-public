# Buttons

Buttons communicate clear commands and use a small set of visual roles.

## Roles

- **Primary:** the next important action in a workflow
- **Secondary:** a visible alternative or review action
- **Quiet:** low-emphasis utility action
- **Icon:** familiar compact control with an accessible name

## Requirements

- Use direct action labels.
- Preserve visible keyboard focus.
- Keep touch targets at least `44px` high or wide.
- Do not rely on color alone for state.
- Keep disabled controls visually distinct and semantically disabled.
- Use shared radius and color tokens.
